# پیش‌نمایش و تست تعادل (مرورگر)

این پوشه یک **آینهٔ مرورگری از قوانین و حس بازی «سه توپ»** است، نه خروجی موتور Godot.
نسخهٔ اصلی یک پروژهٔ Godot 4.3 است؛ چون باینری موتور در این محیط قابل اجرا نبود، قوانین
و ثابت‌های `main.gd` عیناً به Canvas/JS منتقل شد تا بازی بدون Godot هم تست‌پذیر باشد.

## اجرا

```bash
cd preview && python3 -m http.server 8080 --bind 0.0.0.0
# سپس http://localhost:8080
```

## پریست‌های تعادل (کلیدهای ۱ تا ۴ یا `?p=N` در آدرس)

| کلید | نام | قدرت ضربه | حداکثر کشش | میرایی | بُرد یک شوت | نتیجه |
|---|---|---|---|---|---|---|
| ۱ | مطابق `main.gd` | 5.8 | 300 | 3.6 | ۴۸۳px | ❌ غیرقابل‌بردن |
| ۲ | قدرت بیشتر | 9.0 | 320 | 3.6 | ۸۰۰px | ❌ غیرقابل‌بردن |
| ۳ | میرایی کمتر | 5.8 | 300 | 1.2 | ۱۴۵۰px | ❌ غیرقابل‌بردن |
| ۴ | اصلاح‌شده ★ | 11.0 | 320 | 3.6 | ۹۷۸px | ✅ تا ۳ گل بازی می‌شود |

## چرا نسخهٔ فعلی `main.gd` غیرقابل‌بردن است؟

دو مشکل مستقل:

**۱) ترتیب داوری در `_evaluate_shot()`**
`ATTACK_LINE_Y` (۷۲۰) بالاتر از موقعیت شروع توپ‌ها (۱۳۹۰–۱۵۲۰) است، پس شوتی که
توپ را پشت خط می‌برد همان شوتی است که باید دروازه را باز کند. اما باز شدن دروازه
**بعد از** بررسی `passed_between` انجام می‌شود:

```gdscript
if not passed_between:
    _handle_foul("سوختی! ...")   # ← اینجا برمی‌گردد
    return
...
for b in balls:
    if b.global_position.y < ATTACK_LINE_Y:
        _set_gate_open(true)      # ← هرگز اجرا نمی‌شود
```

پس هر شوتی که به دروازه نزدیک شود، «سوختی» اعلام می‌شود و دروازه هرگز باز نمی‌شود.

**۲) بُرد فیزیکی کمتر از فاصلهٔ لازم**
با `linear_damp = 3.6` و حداکثر ضربهٔ `300 × 5.8 = 1740`، بیشترین مسافت یک شوت
`1740 / 3.6 ≈ 483px` است، در حالی که برای رسیدن از `y=1390` به خط ۷۲۰ حداقل
`670px` لازم است. حتی پریست ۳ با بُرد ۱۴۵۰px هم گل نمی‌زند، چون مانع اول (ترتیب داوری)
سر جایش است.

پریست ۴ هر دو را با هم درست می‌کند: باز شدن دروازه پیش از داوری پاس بررسی می‌شود و
قدرت ضربه/کشش کافی است. با آن یک مسابقهٔ کامل تا ۳ گل شبیه‌سازی و تأیید شد.
